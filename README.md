<h1 align="center">江恩股市操盘术 Skill</h1>

<p align="center">中文 | <a href="README.en.md">English</a></p>

一套可直接使用的 AI skill 工具包——把《江恩股市操盘术》里那套"先看供求、再定位置、突破才动手、止损保命"的操盘方法，蒸馏成 16 张按流程顺序排列的能力卡，从入市准备一路排到失败排障。

它不是原书摘要，也不是读后感，而是把书中可复用的方法论拆成可触发、可执行、可测试的 skill 模块。

## 这套 skills 能解决什么问题

- 技术分析读了一堆，真到下单还是不知道从哪一步开始：这里把 16 个步骤排成一条流水线，先告诉你现在该做哪一步、下一步是什么
- 放量不涨到底是主力出货还是正常换手——分不清"绝对成交量"和"相对股本的换手率"，就会把每一次放量都当成信号
- 现在处在高位派发区还是低位吸筹区：同一个"放量滞涨"在高位和低位含义相反，缺了位置语境就会照着信号反向操作
- 一年交易几十次、盯盘盯到心态崩，却说不清自己该多久看一次盘、一年最多做几次、什么时候必须离场休整
- 止损永远设不下去，或者设了又撤、撤了又放宽；账户到底能亏几次，从来没算过
- 亏了只会说"运气不好"，没有一张按症状查错的排障表，也分不清"越跌越补"和"浮盈加码"是两件相反的事

## 蒸馏了什么

16 张能力卡，按"准备 → 诊断 → 选股 → 择时 → 执行 → 持有与纠错"的操盘流程顺序组织，每张卡对应流程里的一步：

- **准备与看盘（流程第 0–1 步）**：`readiness-gate`（入市准备与看盘节奏）、`tape-reading-workflow`（看盘纪律与月 / 周 / 日三图体系）
- **供求与位置（第 2–3 步）**：`volume-supply-diagnosis`（成交量供求诊断）、`seven-zone-positioning`（七区域阶段定位与极端反向）
- **选股与档案（第 4–6 步）**：`stock-type-filter`（标的类型过滤与轮动）、`stock-habits-profile`（个股习性档案与安全位置）、`strength-weakness-ranking`（强弱判定与年度名单）
- **顶底与特殊结构（第 7–7b 步）**：`final-top-bottom`（最终顶底判定）、`low-price-accumulation`（低价吸筹股生命周期）
- **开单与执行（第 8–11 步）**：`pretrade-checklist`（开单前 12 条规则检查）、`capital-stop-loss`（资金与止损管理）、`breakout-execution`（突破买卖执行）、`pyramid-plan`（金字塔顺势递减加仓计划）
- **事件、持有与纠错（第 12–14 步）**：`event-news-reaction`（消息贴现判定与事件反应）、`portfolio-annual-checkup`（持仓年度体检与征兆即卖）、`failure-mode-triage-skill`（失败模式排障与运作方法辨析）

## 两种打包模式：single 与 pack

同一套 16 张能力卡，按两种粒度各编译了一次。两者卡片内容完全相同，区别只在入口怎么命名、清单怎么记。

| | single（单一入口） | pack（compact pack，来源路由） |
|---|---|---|
| 可发现入口 | **1 个**：`gann-stockmarket-control-skill` | **1 个**：`gann-stockmarket-control-skill-router`（来源路由入口；本包没有晋级为独立 skill 的卡） |
| 16 张能力卡放在哪 | 全部在入口的 `references/capabilities/` 里，由入口按路由表按需加载 1 张，任务跨域时最多 2 张 | 同样 16 张，放在 router 的 `references/capabilities/` 里；pack 根目录另有两份清单逐卡写明归属 |
| 触发方式 | 入口 description 直接写清适用情境（建体系 / 走流程 / 做体检 / 按我的情况整改） | router 的 description 以"来源路由入口"表述，进包后按 `capability-destinations.json` 的归属表分流到同一批卡 |
| 升级维护 | 替换 1 个目录 | 替换 1 个 router 目录，并同步 `BUILD_MANIFEST.json`、`capability-destinations.json` 两份清单 |

本包的 16 张卡没有晋级为独立 skill，全部由 router 分发，所以两版的卡片与索引文件逐字节一致，差异只在入口的命名、description 措辞和清单文件。

### 该装哪一种

按你的工作方式选，**只装一种**：

| 你的工作方式 | 推荐 | 原因 |
|---|---|---|
| 用 DSH / Codex / Claude Code 等有 skills 目录，希望列表干净 | single | 只占 1 个入口，16 步一张不少 |
| 要拿清单做审计，核对每张卡归属哪个入口，或按归属表分发给多个 agent | pack | `capability-destinations.json` 逐卡写明 `served_by` 与卡片路径 |
| 只想装一次、不想维护多个目录 | single | 升级时只替换 1 个目录 |
| 想同时留下发布哈希与逐卡归属清单做完整性核对 | pack | 两份清单都在，single 只有 `BUILD_MANIFEST.json` |

> 两版由同一个 Bundle 编译，能力内容一致。**同时安装会重复触发**，请只装一种。

## 效果示例

### 示例 1：连续三周高换手却只涨两个点，该不该跑

**用户问题**

"这票连续三周换手 8%、12%、15%，价格才涨了两个点，主力是不是在出货？我该跑吗？"

**skill 如何判断**

- 进 `volume-supply-diagnosis`，第一步不是判读而是**换手校准**：成交量 ÷ 流通股本 = 换手率，先把"放量"换成股本口径；卡里的输入契约写明"无股本数据不得给换手结论"，只能按价格结构处理
- 量价四象限走查：放量而价格滞涨，落在"派发预警"这一格——书里的原话是"大换手却推不动价格，说明有人在持续供给筹码"
- 位置叠加：同样的放量滞涨在高位是派发预警、在多年低位可能是吸筹活跃，位置交给 `seven-zone-positioning` 与 `final-top-bottom`
- 天量检查与区间波动计数：近期是否出现该股史上极值量；同一箱体内 5% 级震荡往复 10~20 次且上下沿不破，说明吸筹或派发仍在进行
- 输出的是"证据强度 + 下一步验证点"，不是一句"跑"

**最终回答示例**

> 先别问该不该跑，先换算成股本口径：换手率 = 成交量 ÷ 流通股本。三周 8% / 12% / 15% 的换手而价格只涨 2%，确实落在"放量滞涨"这一格，判读是**派发预警**——书里的逻辑是"大换手却推不动价格，说明有人在持续供给筹码"。但这只是证据强度，不是判决：吸筹与派发的最终确认要等区间突破，卡里明确要求不得凭量单方面下结论。第二步补位置：同样的放量滞涨出现在多年低位，反而可能是吸筹活跃，所以要看现价处在七区域的哪一段、上方是否压着历史顶底区。第三步查两件事——近期有没有出现该股史上极值的天量（有则标注"行情结束嫌疑"），以及这个箱体里 5% 级震荡已经往复了几次。至于"换手多高算异常"：卡里引用的 7% 单日警觉线是书中点评给的经验值，个股差异很大（有的票 7% 就深调、有的 15% 还在涨），必须按标的磨合，不能当硬阈值。结论：现在是"派发预警（方向性、未确认）"，动作是减仓观察加等区间突破方向，而不是听一个"跑"字。

### 示例 2：20 万本金，能不能把止损放宽到 -20% 扛洗盘

**用户问题**

"20 万本金，想买一只 30 块的票，止损设在 -2.5%，可我又怕被洗，能不能干脆设 -20% 扛住？"

**skill 如何判断**

- 进 `capital-stop-loss`，第一步不是选止损位，而是算**可亏次数** = 本金 ÷ 单笔最大亏损，门槛是 ≥ 10
- 20 万 × 2.5% = 单笔最大亏 5000 元 → 可亏 40 次，通过；改成 20% → 单笔最大亏 4 万元 → 只够亏 5 次，远低于 10，按卡里的判停条款整单判不过（转 `pretrade-checklist`）
- 止损单机制：与开仓同时下、G.T.C.（撤销前一直有效）、触发后按市场最好价成交，可能比设定价更差
- 五条纪律：每笔必设 / 下了不取消 / 不向扩大损失的方向移动 / 越早越好 / 只在获利了结或交割时撤销
- 浮盈保护：赚到 3~4%（换算）就把止损提到保本位，此后按 `pyramid-plan` 跟进；连续 2~3 笔亏损则退出观望

**最终回答示例**

> 20% 这个数字先不用讨论，算算术：可亏次数 = 本金 ÷ 单笔最大亏损。20 万配 2.5% 止损，单笔最大亏 5000 元，可亏 40 次，达标；改成 20%，单笔最大亏 4 万元，只够亏 5 次，直接判不过——不是"扛不扛得住洗盘"的问题，是账户结构不允许。有一个口径必须说明：书里的原始参数是"3~5 点止损"（1 点 = 1 美元价位），换成 2.5%~5% 是整理者按 A 股做的换算，不是原书原文，所以这个百分比还要按个股波动率再校准。另一条本土风险要写进结论：原书假设止损单总能成交，A 股连续跌停或流动性枯竭时这个假设不成立，止损单可能根本成交不了。至于怕被洗——卡里的立场是"止损被扫后反转"不是撤止损的理由；如果被反复扫损，问题出在入场位选择（回到个股习性档案那张卡），不在止损制度。操作上：30 元买入的同时挂止损 29.25，涨到 31.1（约 +3.7%）时把止损上移到 30.05 保本，之后按金字塔卡逐级跟进。

## 这些 skill 是怎么生成出来的

这套 skill 使用 **[cangjie-skill](https://github.com/kangarooking/cangjie-skill)** 的 RIA-TV++ 流水线生成，整个流程分六个阶段：

1. **整书理解（Adler 分析）**——用 Mortimer Adler 的分析阅读法，对全书做结构、解释、批判、应用四步拆解，先定下"流程驱动而非能力域查询"的蒸馏路线
2. **并行提取**——同时派多个专项提取器（框架、原则、案例、反例、术语），从原文中提取候选方法论单元，本书共得 347 条候选
3. **三重验证筛选**——每个候选必须通过三项检验：书内来源充分（V1）、能给出可执行的走查输入与预期产出（V2）、对读者任务有增量（V3）；归并去重后留下 16 个能力单元
4. **RIA++ 构造**——按 R（原文引用）/ I（用自己的话重写）/ A1（书中案例）/ A2（未来触发场景）/ E（可执行步骤）/ B（边界与盲点）六个维度结构化，书中点数参数换成 A 股百分比的换算一律标注为整理者补丁
5. **Zettelkasten 链接**——按操盘流程给 16 张卡编号（第 0 步到第 14 步），标出每张卡的上下游与"与相邻能力的区分"，生成能力索引与路由表
6. **触发与输出测试**——为入口设计触发盲测（含诱饵题：该触发时要触发、不该触发时要沉默）与实际输出抽检，未通过的回到入口描述重修，复测后再做回归

本书的特殊之处在流程编排：同一原著还有一个"按能力域单点查询"的姊妹技能，因此这次蒸馏刻意走"端到端 SOP"路线——它不回答"某条规则是什么"，而是陪你建体系、走流程、做体检、按你的情况整改。

## 测试与验证

本仓库连生成过程的测试材料一起发布：`evals/test-prompts.json` 是入口级触发与边界用例，`evals/test-results.md` 是逐项评分与修复记录——包含失败与返修过程，不是只留通过记录。

- **触发盲测**：11 例（5 例应触发、3 例诱饵不应触发、3 例边界）。首测 9 例直接正确，例 04、05 被误路由到姊妹技能，修复方式是改写入口 description（补进"节奏整改 / 建体系"情境例句、把分工边界细化），复测两例均正确路由，最终 11 / 11
- **诱饵拦截**：跨技能混淆（12 条规则列举）、非能力域（财报价值投资）、近邻流派（缠论画笔）三类诱饵全部正确拦截或转交，无一误触
- **输出抽检**：2 个代表任务（正常场景的成交量诊断、缺输入边界下的开单检查），输出契约逐项满足；缺项先问不猜值、证据分级不喊单、不承诺点位三类判停条款全部生效，2 / 2 达标
- **口径差异**：抽检中两处口径分歧（周换手与单日 7% 阈值的适用、累计换手的两种算法）按记录显式标注，没有静默取舍
- **测试环境**：测试记录注明测试模型与宿主为 GLM-5.3 子代理 / ZCode Agent 工具，非本仓库运行环境

## 如何使用

先把仓库克隆下来：

```bash
git clone https://github.com/raphael-y7/gann-stockmarket-control-skill.git
```

### 装 single（推荐先试这个）

```bash
# macOS / Linux
cp -r gann-stockmarket-control-skill/single/gann-stockmarket-control-skill ~/.agents/skills/
```

```powershell
# Windows
Copy-Item -Recurse .\gann-stockmarket-control-skill\single\gann-stockmarket-control-skill "$env:USERPROFILE\.agents\skills\"
```

### 装 pack

只复制含 `SKILL.md` 的目录，不要把 `pack/` 下的两个 json 一起拷进 skills 目录：

```bash
# macOS / Linux
cd gann-stockmarket-control-skill/pack
cp -r gann-stockmarket-control-skill-router ~/.agents/skills/
```

```powershell
# Windows
$pack = ".\gann-stockmarket-control-skill\pack"
$dest = "$env:USERPROFILE\.agents\skills"
Copy-Item -Recurse -LiteralPath (Join-Path $pack 'gann-stockmarket-control-skill-router') -Destination $dest
```

> `~/.agents/skills` 是 DSH 的 skill 目录；用别的 agent 时换成它自己的 skills 目录即可（例如 Claude Code 是 `~/.claude/skills`）。

### 怎么确认装好了

装完问一句"帮我按江恩的方法把这只票从头到尾过一遍"，看 agent 是否先读入口、再按路由表只加载一张能力卡（而不是一次性把 16 张全读进来）。再问一句"我的持仓该做年度体检了"，它应当路由到 `portfolio-annual-checkup`，而不是给你一段泛泛的长期持有建议。
